## 分层规则

- `state`：存运行状态，不能兼做数据库表。
- `schema`：明确字段与校验，不放搜索和价格计算。
- `node`：协调一次任务并更新自己负责的状态字段，不直接处理 HTTP。
- `tool`：外部读写、价格算法、业务存取；小项目先放这里，不强加复杂服务架构。
- `graph`：节点与路由；不了解平台 HTML 和 SQL。
- `web`：身份校验、创建运行、SSE、收藏接口；不让浏览器决定可信价格。
- `html`：展示后端结构化结果，不二次计算到手价。
- `jobs`：按固定周期重新查价，与聊天图生命周期分开。

## 开发顺序

字段合同 → 状态 → 可返回固定数据的工具 → 线性图 → 同款规则 → 价格引擎 → 评论与比较 → 业务持久化 → 提醒 → 页面完善。

薄页面和流事件从 Day 1 就保留，Day 6 集中完善交互。这样前五天也能看到进度，不必等最后一天才发现接口不匹配。

## 参考代码：模块装配顺序（独立演示）

下面生成学习顺序，不创建文件。app.ai.agent.multi_agent.schema.shopping_schema 是其他示例共同导入的模块路径。

```python
module_order = [
```

先复制统一合同，再复制使用该合同的模块片段。不要将同一章节多个示例全部原样拼在任意文件里；每段的目标路径和依赖以章节说明为准。
