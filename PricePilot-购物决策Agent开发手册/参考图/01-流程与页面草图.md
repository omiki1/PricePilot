## 图 1：主线与可选并行

```mermaid
flowchart TD
    A[自然语言需求或商品链接] --> B[Manager 与 Intent 动作识别]
    B --> R[Requirement 条件提取]
    R --> C{关键需求是否足够}
    C -->|否| D[等待用户补充]
    D --> B
    C -->|是| E[Search 调用 Amazon 与京东工具]
    E --> F[Normalize 识别同款与替代品]
    F --> G[Price 程序计算付款金额]
    F --> H[Review 提取评论证据]
    G --> I[等待两分支进入终态]
    H --> I
    I --> J[Compare 程序过滤与排序]
    J --> K[Reporter 解释与图片商品卡和比较页]
    K --> L[用户收藏并设定阈值及通过能力门槛]
    L --> M[独立监控任务复采与复算]
    M --> N{满足合格报价与触发条件}
    N -->|是| O[通知日志与邮件]
    N -->|否| P[保存状态并等待下轮]
```

Day 1～3 先采用串行 Price → Review；图中的双分支是 Day 4 可选优化。无结果和分支失败按图编排文档降级，不无限等待。

## 图 2：数据如何连接

```mermaid
flowchart LR
    A[用户需求] --> B[购物运行]
    B --> C[标准商品]
    C --> D[平台与店铺报价]
    D --> E[价格快照]
    E --> F[来源证据]
    C --> G[评论样本]
    G --> H[评论主题与证据]
    E --> I[比较报告]
    H --> I
    C --> J[用户收藏]
    J --> K[目标付款金额]
    K --> L[监控与通知日志]
    E --> L
```

商品与报价是两层；价格快照是报价在某时刻的记录。监控的是明确规格和资格口径，不是一个模糊的标题。

## 图 4：提醒状态

```mermaid
stateDiagram-v2
    [*] --> Armed: 用户开启监控
    Armed --> Armed: 报价不合格或未到阈值
    Armed --> Triggered: 合格付款价达到阈值并登记通知
    Triggered --> Triggered: 价格持续低于阈值
    Triggered --> Armed: 合格价格回到阈值以上并开启新代次
    Armed --> Paused: 用户暂停
    Triggered --> Paused: 用户暂停
    Paused --> Armed: 用户恢复并复核条件
```

通知发送失败的重试属于通知日志状态，不等同于再次跌价；不能通过反复重新布防来实现发送重试。

## V2 阅读图时要注意

双来源搜索不等于跨币种可比；价格合格集合按货币、目的地与规格区分。真实提醒还需要站点与来源许可，未启用时只展示收藏或模拟流程。图片区用 API 授权 URL，购买按钮使用后端选定链接。

## 参考代码：把阶段事件映射为可见进度（独立演示）

未来可用于前后端事件合同测试；阶段完成才显示完成，不提前伪造百分比或商品数量。

```python
STAGES = [
    "intent", "requirement", "search", "normalize",
    "price", "review", "compare", "reporter",
]

def progress_view(events):
    result = {stage: "pending" for stage in STAGES}
    for event in events:
        stage = event.get("stage")
        if stage not in result:
            continue
        if event["event_type"] == "stage_started":
            result[stage] = "running"
        elif event["event_type"] == "stage_completed":
            result[stage] = "completed"
    return result

view = progress_view([
    {"event_type": "stage_completed", "stage": "intent"},
    {"event_type": "stage_started", "stage": "requirement"},
])
assert view["intent"] == "completed"
assert view["requirement"] == "running"
assert view["search"] == "pending"
```
