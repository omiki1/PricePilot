# 节点实施说明：动作分类与条件提取分开

## 每个节点的职责

| 节点 | 输入 | 工作与输出 | 是否需要模型 |
|---|---|---|---|
| Manager | 当前运行与会话 | 校验服务层已允许本次执行，进入主图 | 否 |
| Intent | 当前 query | action=search/compare/price/track | 是 |
| Requirement | query、action、之前已确认条件 | 提取结构化条件并列出待补信息 | 是 |
| Search | requirements | Amazon/JD Tool 搜索或解析指定链接，逐来源状态 | 否；查询词可由模型辅助 |
| Normalize | offers | 字段归一、硬规格比较与证据校验 | 规则为主，模型辅助 |
| Price | offers、资格 | 计算与复核，独占 price_results | 否 |
| Review | 样本及需求 | 去重、主题、证据；独占 review_results | 是 |
| Compare | 合格报价、评论主题 | 硬约束过滤、同口径分组、确定性排序 | 程序主导 |
| Reporter | 结构化比较结果 | 商品卡＋理由＋限制；不更改金额 | 可选 |
| TrackConfig | 明确商品与阈值 | 生成确认卡，不直接写订阅或发邮件 | 否 |

节点内不要直接处理浏览器连接或自由执行 SQL。一个节点先读取状态，再调用边界工具，再验证结果，最后返回自己负责的字段。

## 参考代码 1：Intent 与 Requirement（模块参考）

未来分别放到 intent_node.py 与 requirement_node.py。依赖统一 Schema 和支持结构化输出的模型。提示词可替换为 YAML 加载器返回的字符串。

```python
import json
from langchain.agents import create_agent
from app.ai.agent.multi_agent.schema.shopping_schema import (
    IntentSchema, RequirementSchema,
)

def build_intent_node(model, prompt: str):
    agent = create_agent(model=model, system_prompt=prompt,
                         response_format=IntentSchema)
    async def intent_node(state):
        if state.get("pending_question") and state.get("action"):
            return {"action": state["action"]}  # 澄清回答不重新猜动作
        result = await agent.ainvoke({
            "messages": [{"role": "user", "content": state["query"]}]
        })
        intent = result["structured_response"]
        return {"action": intent.action}
    return intent_node

def build_requirement_node(model, prompt: str):
    agent = create_agent(model=model, system_prompt=prompt,
                         response_format=RequirementSchema)
    async def requirement_node(state):
        previous = state.get("requirements", RequirementSchema())
        context = {
            "query": state["query"], "action": state["action"],
            "confirmed_requirements": previous.model_dump(mode="json"),
        }
        result = await agent.ainvoke({"messages": [{
            "role": "user", "content": json.dumps(context, ensure_ascii=False)
        }]})
        req = result["structured_response"]
        missing = list(req.missing_fields)
        if state["action"] == "search" and req.budget_max is None:
            missing.append("budget_max")
        if state["action"] == "compare" and len(req.target_urls) < 2:
            missing.append("至少两个商品链接")
        if state["action"] in {"price", "track"} and not req.target_urls:
            missing.append("目标商品链接")
        if state["action"] == "track" and req.target_price is None:
            missing.append("target_price")
        missing = sorted(set(missing))
        req = req.model_copy(update={
            "missing_fields": missing,
            "needs_clarification": bool(missing),
        })
        return {
            "requirements": req,
            "pending_question": ("请补充：" + "、".join(missing)) if missing else None,
            "run_status": "waiting_input" if missing else "running",
        }
    return requirement_node

def track_config_node(state):
    req = state["requirements"]
    return {
        "run_status": "awaiting_watch_confirmation",
        "final_report": {
            "kind": "watch_draft",
            "target_urls": [str(url) for url in req.target_urls],
            "target_price": str(req.target_price),
            "currency": req.currency,
            "requires_confirmation": True,
        },
    }
```

该实现展示基本路径。实际入口需验证链接所属平台、同一用户归属和模型字段错误，并把缺失字段映射成人类易懂的问题。模型不得擅自改动用户确认的硬条件；真正的澄清合并应由服务端记录哪些字段本轮允许修改。

## 参考代码 2：Review 分支的失败降级（模块参考）

load_reviews(product_id) 与 analyze(samples, requirements) 为你实现的异步函数；前者只返回有权使用的评论，后者返回 ReviewAnalysis。不要把不可获得的评论能力伪装成空采集成功。

```python
import asyncio


def build_review_node(load_reviews, analyze):
    async def review_node(state):
        results = []
        try:
            for product in state["normalized_products"]:
                product_id = product["product_id"]
                samples = await asyncio.wait_for(load_reviews(product_id), 8)
                if not samples:
                    continue
                analysis = await asyncio.wait_for(
                    analyze(samples, state["requirements"]), 20
                )
                known_ids = {sample["review_id"] for sample in samples}
                for theme in analysis.pros + analysis.cons:
                    if not theme.review_ids or not set(theme.review_ids) <= known_ids:
                        raise ValueError("评论主题缺少有效证据")
                if analysis.sample_size != len(known_ids):
                    raise ValueError("评论样本统计不一致")
                results.append(analysis)
            return {"review_results": results,
                    "review_status": "completed" if results else "empty",
                    "review_error": None}
        except (TimeoutError, ValueError):
            return {"review_results": results, "review_status": "failed",
                    "review_error": "评论超时或证据校验失败，保留已确认结果"}
    return review_node
```

load_reviews 必须先按原始评论 ID 和内容去重；analyze 分批处理大样本。其他来源错误在工具层转成受控异常，不无限重试。

## Compare 与 Reporter 的规则

预算内且硬条件符合的商品才进推荐。按“有证据支持的用户偏好数 → 同币种付款金额 → 稳定商品 ID”做可解释排序；未知不计支持。A 综合首选，B 剩余低价候选，C 剩余某偏好更突出者，不足三款如实展示。

不同币种与地区另组，Amazon 政策要求展示的其他成色报价另列；不污染全新榜。Reporter 使用 ProductCard 和 ComparisonReport，模型只生成解释槽位。找不到合格报价时仍可列候选，但标明暂不能核验付款金额。
