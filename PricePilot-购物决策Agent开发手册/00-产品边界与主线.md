# 00 产品边界与主线

## 第一版做什么

用户通过需求或商品链接进入。Intent 分辨动作，Requirement 抽取条件，搜索 Amazon＋京东并呈现图片；识别同款后算付款金额，评论形成证据，再展示 A/B/C、购买链接、收藏与支持场景下的监控。

| 维度 | 约定 |
|---|---|
| 品类 | 头戴式蓝牙降噪耳机，先跑通一种品类 |
| 平台 | Amazon＋京东；未获权限时保留适配器和明确演示数据 |
| 动作 | search、compare、price、track |
| 来源 | 官方/联盟 API 优先，先 Tool 后 MCP |
| 地区币种 | 京东 CN/CNY；Amazon 按实际获准站点配置，US/USD 仅示例；不默认跨币种排名 |
| UI | 聊天、商品卡、比较视图；图片、普通商品链接、可选联盟链接 |
| 数据库 | 默认 MySQL，或从 Day 1 选 PostgreSQL；不双写 |
| 监控 | 明确商品/币种/目的地/资格与目标付款价；用户确认后开启 |
| 新技术 | Redis 可后补缓存；Neo4j 用于后续型号关系，不阻断主线 |

## 运行配置与真实完成度

`demo_full` 用自建数据完成全部交互。`live_showcase` 展示获准来源能力，但站点级监控/历史关闭。`live_full` 在实际获准范围内开启完整业务，来源能力和站点用途共同决定可用功能。Amazon 相关依据集中见 [接入章](app/ai/tool/Amazon与京东接入.md)。

两源搜索成功不等于可比较：币种、目的地、规格或费用口径不一致时分栏展示。不允许把美元裸价与人民币付款价直接判断谁便宜，也不把“Amazon＋京东均有卡片”当成真实同款到手比价已完成。

## 参考代码：站点功能门槛（独立规则演示）

目标：未来 `app/ai/tool/site_policy.py`。参数由后端审核后的配置提供，不由用户请求体或模型决定。这里只展示站点级提醒开关；来源自身 tracking_allowed 还要单独检查。

```python
def tracking_enabled_for_site(profile: str, amazon_active: bool,
                              site_tracking_permission: bool) -> bool:
    if profile == "demo_full":
        return True   # 只能处理演示数据与模拟通知
    if profile == "live_showcase":
        return False
    if profile != "live_full":
        raise ValueError("未知运行配置")
    if amazon_active and not site_tracking_permission:
        return False
    return True

assert tracking_enabled_for_site("demo_full", False, False)
assert not tracking_enabled_for_site("live_showcase", True, False)
assert not tracking_enabled_for_site("live_full", True, False)
```

## 核心规则

付款价和未来返现分开；资格未知不填满足；运费未知不填零；同系列不等于同款；评论结论必须有证据；程序决定金额和排序；模型只辅助理解与解释。当前最低只能限定为本次已接入且核验通过的可比来源。
